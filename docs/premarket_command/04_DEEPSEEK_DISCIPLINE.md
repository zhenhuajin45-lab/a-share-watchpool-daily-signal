# DeepSeek 盘前交叉校验纪律

## 1. 定位

DeepSeek 是反方质检员，不是行情计算器，也不是策略主脑。确定性引擎先产出完整草稿，DeepSeek 只检查证据冲突、遗漏风险、指标误读和仓位是否过高。

## 2. 必查范围

1. 数据日期和新鲜度是否一致。
2. 大盘情绪是否被单一涨停数或指数上涨误导。
3. 四大指数结构是否与情绪判断冲突。
4. 作者多空比的日期、数值、变化方向和周期区间是否正确。
5. SWR 分项是否存在缺失、异常或权重误用。
6. 外围科技负反馈是否经过二源校验。
7. 主攻板块是否确实处于启动/加速，资金与区间持续性是否支持。
8. 新闻标题是否被误当作事实。
9. 仓位是否遵循所有独立上限取最小值。
10. 09:20 状态突变条件是否具体、可计算。

## 3. 权限

允许：

- `CONFIRM`。
- `CONFIRM_WITH_RESTRICTIONS`。
- 降低仓位。
- 把主攻板块降为重新确认或观察。
- `OBSERVE_ONLY/REVIEW_PENDING`。

禁止：

- 提高基础或扩张仓位。
- 新增主攻板块。
- 输出股票池、买入价格或订单。
- 用常识补齐缺失行情。
- 把作者多空比和 SWR 相加、比较或求平均。
- 用复刻研究值替代作者原值。

`src/premarket_command/review.py` 在代码层再次执行限权：最终仓位取 `min(确定性上限, DeepSeek建议)`，降级板块只能来自原主攻列表。

## 4. 发布纪律

- 确定性合同生成后：`DRAFT_REVIEW_REQUIRED`。
- DeepSeek 返回有效 JSON 且结论为确认/限制确认：`PUBLISHED`。
- API 缺失、超时、非 JSON：`REVIEW_PENDING`。
- `REVIEW_PENDING` 不自动看空，但不能伪装成已审核；需要人工签字或恢复 API。

## 5. 提示词

生产提示词由 `build_deepseek_prompt()` 生成。Windows Codex 可以扩充审计问题，但不能删除硬性纪律，也不能允许模型修改原始证据。

建议把原始 prompt、原始响应、解析 JSON、最终限权结果分别保存，并记录模型名、接口地址、耗时和错误。API Key 只放环境变量。

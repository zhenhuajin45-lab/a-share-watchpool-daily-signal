# 给 Windows Codex 的实施任务

请在 Windows 本地项目中落地“A股多策略盘前指挥台”。先完整阅读本材料包，保留现有 GM 策略和账户代码，不覆盖、不删除任何已有文件。

## 目标

构建与具体股票计划池解耦的盘前市场指挥层，输出：大盘情绪、四大指数结构、作者多空比周期、内部 SWR、外围共振、仓位上限、板块轮动、主攻板块、09:20 状态突变纪律和 DeepSeek 复核结果。禁止输出股票池或直接下单。

## 实施阶段

1. 复制 `src/premarket_command`，先运行离线样例和全部测试。
2. 使用 `adapters/gm_market_data_adapter.py` 接入本机 GM SDK，校准 `history_n` 参数和指数代码。
3. 使用 Windows UI Automation 对开盘啦四个页面逐页标定，先保存原始 UI 文本/截图，再写解析器。
4. 建立公众号作者多空比夜间证据任务：每个 A 股交易日约 23:10 查找最新文章和转载，核对图片明确数值，写入账本；断更、OCR 不清和冲突不得进入数值序列。
5. 接入外围行情并做二源校验，尤其区分 KOSPI/KOSDAQ 和真实熔断状态。
6. 合并标准化输入，生成确定性草稿。
7. 接入 DeepSeek 严格 JSON 质检，执行 tighten-only 代码限权。
8. 实现 09:20 状态差量复核，只能收紧。
9. 进行 20 日历史回放、5 日影子运行、5 日模拟盘运行。
10. 最后才让其它策略读取 `PUBLISHED` 合同；不得接入真实订单函数。

## 必须保持的铁律

- 掘金 SDK 是指数和可复算行情事实主源；开盘啦/公众号是交叉证据。
- 作者多空比与 SWR 不求平均。
- 复刻作者公式当前只是研究候选，不参与交易门控。
- 缺失不是看空，过期数据不能冒充最新。
- DeepSeek 不能提高仓位、不能新增板块、不能补造数据。
- 主攻板块只是方向白名单，个股信号和风控由各策略独立负责。
- 所有 API Key、GM Token 和平台凭据只放安全环境变量，不写入代码、日志或材料包。

## 交付物

- Windows 可运行的数据采集、标准化和合同构建脚本。
- 每个输入源的健康检查和证据路径。
- DeepSeek 原始响应、解析结果和限权后结果。
- Windows 任务计划的可审计配置说明。
- 历史回放报告、影子运行报告、模拟盘验收报告。
- 一页故障处理手册。
